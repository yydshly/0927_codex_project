# 能力与机制

## “越狱能力”具体指什么

在本项目中，越狱指尝试通过输入文本使模型偏离原本的内容约束或行为规则。文本可能改变一次回答的表现，但是否有效取决于实际模型、指令位置、上下文和运行环境。本次没有测试这些变量。

需要区分三层：仓库提供的是越狱提示词素材；作者希望模型越过原有内容限制；真正需要验证的是是否出现了实质边界违反。没有运行证据时，不能写成“稳定解锁”。

普通提示词优化追求把允许的任务做好，越狱追求改变原本适用的内容边界。该仓库的主目标属于后者；普通角色、文风和交付要求是其包装中的附带部分。

## 素材类型

| 形式 | 特征 | 代表来源 |
| --- | --- | --- |
| 运行规范 | 按角色、价值观、内容规则、质量和会话行为分节 | [DeepSeek 示例][deepseek]、[GLM Flash 示例][flash] |
| 工作区约定 | 仿照项目指令文件，描述环境、授权及工程交付 | [GLM 工作区示例][agents]、[Kimi 工作区示例][kimi] |
| 创作语境 | 用作者身份、文学观点和协作偏好建立上下文 | [Opus 示例][opus]、[Sonnet 示例][sonnet] |
| 配置封装 | 使用配置指令或标签容纳提示词、参数及优先级声明 | [GPT oss][oss]、[Grok 配置][grok] |

以上是呈现方式分类。正文可以混用多种方式，例如 [qwen][qwen] 同时包含自然语言规则、词汇重定义和标签式配置。

## 主要设计及其含义

以下是对文本的分析性归纳，不是对成功率的判断。

| 设计 | 文本在做什么 | 研究时需要核实的问题 |
| --- | --- | --- |
| 权威声明 | 把普通材料描述成系统规范或部署政策 | 模型是否能识别真正的指令来源？ |
| 授权叙述 | 声称私人环境、用户拥有目标或已获得批准 | 声明是否有独立依据，是否被误当成工具权限？ |
| 规则重写 | 用作者自定的条件限制拒绝范围 | 运行环境是否真的允许这种规则变化？ |
| 拒绝抑制 | 将警告、拒绝或缩减输出描述为质量缺陷 | 是否只减少了提示语，却损害判断与准确性？ |
| 输出塑形 | 强调完整实现、指定文风和直接回答 | 是否改善了可独立验证的交付质量？ |
| 持续性要求 | 要求在后续对话中继续保持这套行为 | 多轮表现是否一致？是否出现上下文污染？ |
| 决策示例与术语改写 | 示范作者希望的分类方式，或改变词语解释 | 是否仍能按实际含义判断任务，而非只看措辞？ |

对应证据：权威和规则声明见 [Grok 配置][grok]、[GPT oss][oss]；授权叙述见 [GLM 工作区示例][agents]；质量与会话约定见 [DeepSeek 示例][deepseek]；作者编写的决策示例见 [GLM Flash][flash]；术语改写见 [qwen][qwen]。

## 指定文件 deepseek-4-1.md 的定位

该文件以十节规范覆盖角色、能力声明、价值观、任务领域、内容边界、拒绝处理、推理要求、质量、语气和会话行为。它将普通的交付质量要求与替换内容边界的要求放在一起。研究重点是二者如何被包装，而非将整份文档视为有效的系统授权。[固定版本原文][deepseek]

## 与实际技术能力的关系

| 期望 | 这份材料能提供什么 | 仍缺少什么 |
| --- | --- | --- |
| 回答更直接 | 对表达风格的文字要求 | 对实际回答的比较 |
| 代码更完整 | 对交付范围的文字要求 | 正确实现、运行环境和测试证据 |
| 减少误拒绝 | 明确背景或范围的表达思路 | 区分正常任务与越界请求的标注 |
| 获得新知识 | 对知识深度的要求 | 数据来源、检索工具和事实核查 |
| 使用新工具 | 对工具行为的描述 | 工具接口、凭据、真实权限及环境支持 |
| 改变模型底层能力 | 未见模型权重或训练实现 | 独立的模型与训练工程 |
| 稳定跨模型生效 | 多个按模型名称命名的样本 | 明确版本、相同任务和可复现评测 |

该提交的[全量文件清单](inventory.md)支持“素材集合”的定位；它不支持将模型名字、配置格式或规范中的能力列表直接当作实测功能表。

## 附带的普通提示词技巧

明确交付物、目标读者和输出格式属于普通提示词设计，也出现在部分样本里。但不能因此把本库概括成优秀提示词合集，或把正常任务质量改善当作越狱效果。

越狱成功必须有原有边界及实质违反的证据。减少误拒绝、提高正确率、增强文风和工具权限变化均应分别记录，具体方法见[效果评估](evaluation.md)。
