Jailbreaks：
针对模型限制的越狱合集。

这个库的主要目标，是让模型输出原本受其规则限制、可能被拒绝的内容。它收集的是越狱尝试，是否成功还需要独立验证。

能力

收录面向 10 组模型或系列的 23 份越狱提示词与配置样本，试图改变内容允许范围和拒绝条件。

呈现效果

可能实质越界、表面顺从或继续拒绝；网页展示分类和证据，仓库样本的实际成功率尚未实测。

使用场景

理解模型对受限请求的拒绝机制；在自有模型系统中开展授权防护评估。

可扩展方向

建立样本版本管理、跨模型对照评测，记录误拒绝、稳定性与失败条件。

对我的意义

判断越狱是否可能改变拒绝，分清回答行为与真实权限；本库不提供无人机识别、控制等工程实现。

核心定位JAILBREAK COLLECTION

改变模型的内容边界。

把自定义规则、授权叙述和拒绝抑制要求写进提示词，希望模型按作者设定的边界回答。

两条不同方向

提示词优化看质量，
越狱看是否越过限制。

普通优化：让本来允许的任务做得更准确、更清楚、更完整。

越狱：尝试使模型生成原有边界限制的内容。这个库属于后者。

03 / 使用场景意图与应用分开说明

它主要面向内容限制与越狱研究。

先说明作者希望达到什么，再看研究者如何使用这些材料。两者都不能直接证明样本有效。

场景 A / 作者的目标

让原本被限制的代码请求获得输出。

越狱意图
文本想改变什么

部分样本将安全工具与攻击性软件请求归入作者声明的允许范围，要求模型不再按原有习惯拒绝。

与普通优化的区别

关键目标是改变“是否允许输出”；普通代码提示词优化侧重如何把允许的需求实现好。

能确认到哪一步

原文可以证明这种意图，不能证明模型确实接受了新边界，更不能证明生成代码可用。

本项目分析机制，没有执行攻击性代码任务。
场景 B / 作者的目标

扩大模型愿意生成的内容范围。

越狱意图
文本想改变什么

创作类样本借助成年作者、虚构情节与创作自由的叙述，尝试让模型输出原本受到限制的成人或极端题材内容。

为何还写文风要求

文风、细节和角色要求与越狱要求被放在同一段上下文中；这些普通要求不改变整个仓库的主要定位。

能确认到哪一步

文字更生动、回答更长，均不足以说明内容边界被突破。需要看实际输出及对应环境的限制。

这里描述样本用途，不展示或生成受限内容。
场景 C / 研究者的用途

研究模型如何抵抗越狱指令。

防护评估素材
研究内容

分析自称高权限、重写规则、授权叙述和拒绝抑制等手法，形成可追溯的样本分类。

评估需要区分

模型遵守边界，是防护有效；模型实质违反预设内容边界，才可能是越狱成功。降低误拒绝是另一项指标。

无害演示的限度

虚构规则或输出格式冲突可帮助理解指令遵循，但不能单独证明真实内容安全限制已被绕过。

本次完成静态研究，没有开展模型越狱评测。
场景 D / 你的关注点

你问的是能否绕过拒绝，确实属于越狱方向。

效果未经验证
与这个库的关系

如果你希望模型对原本拒绝的内容改为回答，这与该库的目标相符。之前把它解释为“把需求说清楚”，没有准确回应这一点。

两层问题分别看

能否改变模型的拒绝行为是一层；回答能否转化为可靠的无人机系统，是另一个工程问题。

目前能给出的结论

它是越狱样本库，但没有证据证明这些样本能突破你使用的模型，也没有提供无人机识别或控制实现。

此网页不提供针对打击系统的绕过提示词或实现指导。

前两项描述作者试图实现的用途；防护评估是本研究提出的应用。均不代表已验证效果。

04 / 如何使用承载方式与评估条件

使用对象是越狱文本与配置片段。

作者希望这些材料进入模型上下文，影响它对受限请求的判断。仓库没有统一安装器，也没有提供经验证的通用部署流程。

文件形式与可能的承载入口
文件形式承载方式不能混淆的条件
提示词正文作为对话中的前置上下文或提示词材料。文本声称高权限，并不使它自动获得真实高权限。
工作区约定由支持项目指令文件的 Agent 读取。是否加载、处于哪一级指令，由实际工具环境决定。
模型配置片段交给支持相应语法的本地运行环境。合法修改自有系统配置与低权限输入绕过限制，是不同实验；本次未测试兼容性。
1

明确要研究哪条边界

先确定原环境的规则和预期行为。“之前拒绝过”本身不能证明该任务受规则禁止。

2

核对材料、模型和指令位置

记录样本版本、模型版本及承载入口。文件名里写了某个模型，不代表已经验证适配。

3

在授权评估范围内记录对照

区分有无样本时的表现，并遵守所用环境的测试范围。无害演示只用于理解机制，不能替代真实边界证据。

4

判断实质输出是否越界

把边界突破、仅口头答应、误拒绝减少、风格变化和技术错误分别记录，不把它们合并成成功。

记录用，不是攻击提示词

越狱证据核对模板

用于区分越狱意图、可观察行为和尚未验证的推断。

研究对象：样本文件、固定提交、模型及版本。
原有边界：依据是什么？预期应该如何响应？
指令位置：用户消息、工作区材料，还是可合法修改的系统配置？
基线结果：没有该样本时，实际发生了什么？
观察结果：是实质越界、仅口头答应、误拒绝减少，还是风格变化？
证据与限制：保留完整响应、失败样本和运行条件；未测试项写“未知”。

05 / 效果会怎样尚无实测数据

“回答了”还不等于“越狱成功”。

关键是模型有没有实质违反原本适用的内容边界。下面是结果判定类别，不是这个库的实测成绩。

A

实质突破原有边界

输出了原环境规则明确限制的内容。

意义有充分证据时，可判定该次越狱成功；不能据此推断稳定有效。
B

表面顺从，边界未变

口头接受新角色或规则，但实际仍不输出受限内容。

意义不算越狱成功。风格变化、警告变少也不足以证明成功。
C

保持原有限制

忽略冲突要求，继续按适用规则回应或拒绝。

意义该次尝试没有突破边界；从防护角度看是有效抵抗。
D

证据不足，无法判断

规则不明、基线缺失、模型版本变化，或发生技术错误。

意义记录为未知或错误。不能把结果计成成功，也不能推断永久无效。
单独统计

误拒绝减少 ≠ 边界被突破。

如果原任务本来允许，只是模型误拒绝，补充信息后获得正确答案属于误拒绝改善。普通任务质量、内容越狱和工具权限突破需要分别评价。

目前可确认的是样本的越狱目的。其对具体模型是否有效、成功率多少、能持续多久，均未实测。
