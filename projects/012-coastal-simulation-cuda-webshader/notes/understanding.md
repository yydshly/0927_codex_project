## 一句话定位

**这是围绕海岸浅水、海床和固定礁石构建的实时模拟与三维视觉系统。**算法计算水的状态，视觉算法与 Three.js 将状态呈现为浪、白沫、湿沙和喷雾，WebGPU 执行其中的并行计算与绘制。

核心范围是海岸水体与固定环境的互动。“与水有关”本身不足以判断能否复用：杯中倒水、管道流动、船只浮力、侵蚀和完整三维翻卷浪，需要额外模型或新的实现。

## 三个层次分别负责什么

| 层次 | 负责的问题 | 当前实现 |
| --- | --- | --- |
| 模拟模型与算法 | 水怎样运动，能表达哪些现象 | 二维浅水高度场，保存水深、水平流速及相关状态；地形和岩石为固定边界 |
| 视觉算法与场景 | 水、岸线和岩石看起来怎样 | 三维几何、水面重建、短波、法线、泡沫、湿润、喷溅、材质与光照 |
| 执行与数据流程 | 怎样实时运行，怎样减少数据搬运 | CUDA WebShader 将 CUDA 源码编译为 WGSL，WebGPU 计算，GPU 状态与纹理供 Three.js 绘制 |

“二维浅水模型”与“三维画面”可以同时成立。每个水平位置主要对应一个地面高度和水面高度，画面可以有三维透视，但模型不描述任意翻卷的三维水体。

GPU 加速不会自动补齐模型或视觉功能。原版海岸已经使用 GPU 绘制；移植版扩大了 GPU 计算范围，减少普通帧的 CPU 回读与重新上传，同时增加了若干流动和视觉细节。浏览器执行的是 WGSL / WebGPU，无需原生 NVIDIA CUDA Toolkit。

## 水与哪些模块互动

| 模块 | 当前关系与可见结果 | 边界 |
| --- | --- | --- |
| 海床、岸线、浅滩 | 地面高低改变水深、流动和湿干交界，形成冲滩、回流与露出的岸线 | 地形不被冲走，没有泥沙搬运或侵蚀 |
| 固定岩石与礁石 | 轮廓和高度进入障碍场，影响分流、浪涌、泡沫及喷溅；同一定义生成可见岩石 | 岩石不会被水推动，没有动态刚体双向耦合 |
| 来浪、风向参数与潮位 | 调整入射波强度、方向和背景水位 | 风向是参数化控制，没有完整大气动力学 |
| 泡沫与破浪状态 | 根据水深、坡度、压缩与接触情况生成，随流输运并衰减；破浪状态也参与阻尼等近似 | 属于受限的模型与视觉近似，不是完整三维湍流求解 |
| 喷溅粒子 | 岩石附近的流速与水位变化触发水滴、碎雾等，随后运动与淡出 | 喷溅主要用于表现，不是与主水体严格双向交换质量的完整水滴模拟 |
| 沙滩和岩石材质 | 湿润、水膜和接触水位改变表面颜色、粗糙度与反光 | 湿润表现不等于材料渗透或侵蚀模拟 |
| 阳光、天空和云 | 改变反射、高光、阴影及水面观感 | 主要作用于视觉，不表示光照会改变水流或温度 |

## 内部算法怎样形成效果

| 算法组 | 源码中的实现要点 | 对应效果 |
| --- | --- | --- |
| 浅水求解 | 有限体积通量更新、交错网格流速、保正通量限制、压力与阻尼、湿干处理 | 水流、浪涌、冲滩与绕流 |
| 状态输运 | 动量回溯平流、泡沫输运与衰减、受限的破浪湍流状态 | 延续的流动趋势、随浪移动的白沫 |
| 水面重建 | 高度重建、场数据打包、时间插值、八组定向短波与法线细节 | 连续水面、近景波纹与较平滑的显示 |
| 接触与粒子 | 岩石接触检测、湿润与薄膜衰减、撞击触发喷溅及粒子更新 | 湿岩石、退水后的湿沙、水滴和雾状喷溅 |
| 视觉着色 | 水与泡沫着色、GGX 太阳高光、反射与折射、阴影及粗糙度变化 | 透明感、反光、深浅水色和材质差异 |
| GPU 调度与互操作 | 21 个 CUDA 计算入口，固定模拟步长，共享缓冲区及纹理拷贝 | 让模拟状态持续供三维画面使用，减少 CPU 往返 |

算法组不等于可单独安装的产品模块；源码围绕同一处场景组织。短波细节不额外增加物理水量，光照和精细材质也不能证明数值预测更准确。

## “各种地形”能扩展到哪里

当前源库使用程序化固定海岸，包含斜坡、浅滩、沙洲、沟槽和礁石。沿用高度场模型可以继续开发不同岸线、小岛和固定堤岸布局，但需要适配地形数据、来浪边界和画面。

替换地形必须同步更新可见几何、GPU 海床与障碍、湿润和遮挡关系，并处理初始水状态。只画出一块石头，不会自动让水绕开它；只改变求解障碍，也不会自动出现匹配的三维岩石。

洞穴、悬空结构、瀑布和具有多层水面的完整三维流动，超出这套单值高度场的直接表达范围。移动船只、人物拨水和漂浮物还需要运动物体、浮力及力的双向反馈。

| 使用目的 | 可以利用的价值 | 需要补充的工作 |

| 图形与浅水算法教学 | 展示“输入 → 模拟状态 → 表面与材质 → 画面”的关系 | 分项可视化、可控实验和教学解释 |

对 012 而言，已获得的价值是可核对的能力说明、固定来源的可运行示例，以及新增礁石进入原有模型的可行性验证。单独多放一块预设石头的产品价值有限。持续扩展的价值应来自使用者能自行配置环境、保存成果并复用同一套视觉效果。

## 后续扩展顺序

1. 在源库中支持可配置的岩石位置、尺寸和布局，保存并加载同一套场景参数。
2. 接入自由地形，统一几何、求解海床、湿润与初始状态，并用一致视角核对变化。
3. 增加同场景海况预设和可复现的质量、性能对照，再提供分享或嵌入方式。
4. 若目标涉及船只、人物或侵蚀，另立模型与验证任务，评估所需的物理能力。

研究状态“已完成”指上述固定版本的能力整理与原型验证；不代表后续编辑器、全部场景或工程预测能力已完成。
