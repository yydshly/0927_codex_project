## 核心判断

该库的主线是 CUDA C 的限定子集到 WGSL 的转换，后接 WebGPU 运行时。JavaScript 保留主机侧职责：分配 GPU 缓冲区、标量参数、线程块和网格、多个 pass 的先后次序。指针参数成为 storage buffer，共享内存成为 workgroup memory，索引内建量和同步语义按 WebGPU 对应模型转换。粒子样例让 Three.js 读取相同 GPU 缓冲区，减少每帧读回。

编译器不承诺任意 CUDA 兼容。上游明确拒绝某些布局和双重可写绑定，WGSL 验证器仍是最终检查。Three.js 桥接锁定 r186，因为使用内部缓冲区 API。浏览器运行需要 WebGPU、localhost 或 HTTPS；浏览器应用无需 CUDA Toolkit，原生 CUDA 检查才需要。

## 效果整理

用户指出本地俯视图不像现实物理场景。为把数值解释与沉浸画面区分，展示页增加了同一作者的 [coastal-simulation CUDA WebShader](https://github.com/SamG-Coder/coastal-simulation-cuda-webshader) 独立应用入口。2026-09-27 在内置浏览器的独立页面观察到实时三维岸线、岩石、浪涌和白沫；跨站 iframe 在本站页面只呈现空白，所以改为带有清晰来源标注的截图入口，点击直接打开作者原页。入口图像复用项目 008 捕获的原版 coastal-simulation 画面，不能当作移植版截图或本地模拟输出。它和下方本站自行实现的港湾教学模型是两种不同来源和精度的展示。

在用户希望看到统一现实场景后，本项目新增了“风浪进入港湾”综合演示：外海边界叠加两个波频率，二维线性浅水波更新水位与面中心速度，水深和固体边界定义浅滩、岸线与防波堤。泡沫点读取同一速度场移动；外海与港内测点读取同一水位场并绘制时间曲线。浪强、潮位、视图与局部点击扰动可交互。数值网格、港湾形状和参数为教学示意，没有实测地形、校准边界、破碎波与完整湍流，也没有性能或误差验证。它是本地 JavaScript Canvas 模型，不应归为上游 CUDA WebShader 已整合的样例。

本项目对上游 50 个入口按表现形式重新分为五组：动态物理 8、三维与体数据 7、图像与纹理 21、数值与信号 10、几何与渲染 4。分组是本站研究导航，并非上游官方分类。完整逐项信息存于 [效果目录](../web/catalog.json)。页面顶部另做十二个独立的 Canvas 算法样机，从算法原型推导适合的目标画面：多频波叠加→海岸、示踪粒子平流→交互墨水、N 体引力→星系、Sobel 卷积→视觉扫描、等值线提取→地形、Mandelbrot 迭代→分形艺术、体积采样→科学扫描、光线反射→材质摄影棚、低差异采样→点云、小波→脉冲分析、双调排序→数据编排、双三次插值→纹理放大。每个样机连接一个上游 CUDA/WebGPU 真实例子。

为回答“什么时候用”，另建 [现实用途索引](../web/applications.json)，逐项为 50 个上游样例写明一个可延伸的现实任务、采用条件以及输入到结果的路径。这些是本站基于算法行为的应用推演，不是上游已交付的完整产品；上游原样例的事实仍以 catalog.json 和各样例 README 为准。页面明确区分两类信息，并提示最有价值的采用条件：有受支持的 CUDA 计算、网页端反复处理大量数据、目标浏览器支持 WebGPU 且能验证数值与速度。溃坝 SPH 当前慢于实时，海洋 FFT 不包含靠岸破浪，金融/物理场景需要各自独立验证。

这十二个样机是本站 JavaScript 实现，不是 `cuda-webshader` 的执行输出。多频波叠加未实现完整海洋频谱和逆 FFT；流场未实现上游投影求解；二维等值线是三维 Marching Cubes 的截面类比；本地光线反射不是完整路径追踪；点云使用 Halton 而非上游序列。它们用于比较画面方向，精确功能、结果和性能仍需查看并验证上游原样例。

重点建议观看：

1. FFT 海洋：频谱、逆 FFT、高度和坡度进入三维海面，与你当前海岸研究关联最直接。
2. 交互流体：拖动搅动粒子，观察平流、力、扩散与 FFT 投影的组合。
3. 粒子碰撞、轨道粒子场、N 体引力：观察计算状态持续留在 GPU，并接入渲染。
4. 光流、双目视差、Sobel、降噪和卷积：理解多 pass 图像处理与 CUDA/WGSL 对照。
5. Marching Cubes、Bucky 网格和体渲染：查看体数据转几何或直接射线步进的不同路径。
6. 路径追踪、递归四叉树和贝塞尔：展示复杂辅助函数、递归调度或动态子任务的能力边界。
7. Chrono SPH 溃坝：实验性端口，原版物理内核可运行，但上游明确说慢于实时。

## 验证证据与局限

上游 2026-09-12 的 VALIDATION.md 记录 144 项 Node 检查、79 项浏览器 GPU 数值/渲染检查、5 项原生参考检查通过，20/20 CUDA/WebGPU 对照工况完成数值验证。该报告所测的是当时的版本和设备，不等于本页 50 个目录项均在本站逐项实测。

上游 2026-09-11 性能报告使用 RTX 5080，区分 GPU timestamp、普通 CUDA launch、CUDA Graph 与主机墙钟时间。计算包含重复的 GPU 驻留缓冲区，但排除编译、分配、初次上传和结果读回；粒子项只测计算，不测画面帧率。因此页面只列代表性数值并保留条件，不用比值做普遍性能承诺。

本站实际完成：提取上游公开目录的 50 个样例链接，建立可搜索、分类、切换的静态展示页；新增十二个可观看的本地算法画面与筛选、暂停控制，并让屏幕外样机在进入视野时才开始计算；检查目录 ID 唯一、链接结构正确，并构建静态产物。在当前浏览器的独立上游页面中，观察到 FFT 海洋样例生成 WGSL、GPU 接受着色器并绘制动态海面。其余 49 项未逐项运行。对远端 iframe 的加载事件，只能观察页面响应，不能跨站读取其 WebGPU 状态；在当前浏览器中，页内跨站嵌入海洋样例曾持续空白，因此页面提供超时提示和独立窗口入口。目标设备的性能均未在本项目重新验证。

## 个人应用路线

与 006 Three.js、008/009 海岸模拟和 010 算法实验室相接时，先选一个边界清楚的计算步骤，比如粒子输运或高度场更新。准备固定输入和独立参考数值，比较当前实现、手写 WGSL 与 CUDA→WGSL 的误差、画面和目标设备耗时，再决定是否引入编译器。不要把上游性能报告当作你设备上的性能保证。
