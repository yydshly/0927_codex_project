WHAT IT MEANS FOR YOU

对你最直接的意义

它让“看一张设备图”变成“在空间中定位、检查和操作设备”。本页的风电场已经用到场景绘制、镜头控制、点击选择和重复物体绘制。

做原型先用官方示例验证模型展示、交互和画面效果，快速判断体验是否可行。

做业务页面接入自己的模型与设备数据，形成巡检、产品展示、培训或空间可视化应用。

做技术选型场景变大后先测量瓶颈，再决定是否需要 LOD、实例化，或研究这条 GPU 渲染实验。

能力边界：three.js 主要解决三维呈现。业务后台、模型制作与转换、告警规则需要另做；真实物理模拟通常还要接入物理引擎。官方示例是参考代码，不等于一键可用的产品组件。基础概念 ↗ 物理能力说明 ↗

03 / HOW IT WORKS

原 PR 真正研究的流程

核心价值是让 GPU 组织更细粒度的绘制工作，并针对不同大小的三角形选择合适路径。

01
⌁

筛选

把三角形编成小组。GPU 排除镜头外的小组，并按投影到屏幕上的误差选择模型精度。

02
◇

分流

小三角形由 GPU 计算程序逐像素绘制；大三角形走显卡常规绘制路径。

03
▦

上色

先记住每个像素最终看到的三角形，再读取几何与纹理，为可见像素计算颜色。

WHAT CHANGES

和常规 three.js 有什么不同？

常规 three.js 已提供物体级的视野剔除、距离 LOD 和重复绘制。这个实验把选择细化到三角形小组，并让 GPU 生成后续任务，加入小三角形的自定义绘制路径。它探索的是渲染流程的控制权与任务粒度。

04 / WHERE IT MATTERS

适合什么样的产品？

three.js 可用于不同规模的网页三维产品；下面这些场景尤其值得进一步研究大场景优化。

01 / 工业

工厂与风电场数字孪生

设备密集，值班员常在“全场概览”和“单台巡检”之间切换。远近精度随视角变化，有助于把预算留给正在查看的设备。

02 / 建筑

BIM 与大型工程审阅

建筑构件、机电管线数量巨大。可按视角处理可见结构，再逐步补齐点选、剖切、批注与协同。

03 / 空间内容

城市、遗产与扫描场景

扫描模型往往非常精细。全景浏览需要控制几何量，靠近建筑或文物时再恢复细节。

PRODUCT PATH

如果做成产品

从“研究示例”走向“上传大型模型即可在线巡检”，还需要模型自动分块、多档精度生成、按需加载、材质和光照、交互工具，以及真实设备上的性能测试。这是可扩展方向，属于本项目的产品推断。

05 / EVIDENCE & LIMITS

研究依据与判断边界

原 PR 于 2026 年 5 月合并，作者将其描述为 GPU 驱动的软件光栅化实验，称当前示例涉及超过十亿三角形。源码中这个数字由大量重复茶壶按最高精度估算；每帧实际处理的数量会随视角与精度选择改变。它不是任意模型的性能承诺。
