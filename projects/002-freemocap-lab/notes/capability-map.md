# FreeMoCap 能力全景图：文字说明与来源

整理日期：2026-09-27。版本基准：v2.0.0-alpha.25。

## 本质与数据来源

FreeMoCap 是一套开源无标记动作捕捉系统，将采集、同步、相机标定、姿态识别、三维重建、后处理与导出连接起来。其核心产物是身体关键点随时间变化的三维位置。

多视角三维重建要求同一时刻至少有两个有效视角观察目标点。输入可以来自现场连接的多台摄像头，也可以是提前录制并对齐时间的多角度视频。离线处理时无需连接摄像头，但仍需要与录像对应的标定信息；相机移动后要重新标定。单目采集和二维识别不等于多视角三维重建。

## 技术链路

1. **采集与同步**：组织各摄像头的画面，使参与重建的帧对应同一时刻。
2. **相机标定**：使用已知尺寸的 ChArUco 板估计相机内参、畸变以及相机间的位置与朝向。
3. **二维识别**：使用 RTMPose、MediaPipe 等检测路径，得到各个视角里的身体关键点。
4. **三维重建**：对二维点去畸变，利用同名关键点和投影矩阵建立约束；通过 DLT 与 SVD 求解三维位置，并进行重投影检查与异常观测处理。
5. **时序与骨架处理**：平滑、短时缺失处理、骨骼长度等约束。具体模块与生效设置依版本及实时/离线路径而异，不能假定所有流程共用相同设置。
6. **导出**：保存坐标序列、追踪器定义、标定信息等结果，并按配置接入 Blender 工作流。

理想平行、同焦距双目可以用 `Z = fB / d` 解释深度关系，其中 f 为像素焦距，B 为基线长度，d 为视差。实际多相机算法采用一般投影模型，并不要求所有摄像头平行。

## 输出与效果

- **骨架回放**：从不同方向观察重建的身体运动与轨迹。
- **数据文件**：NPY、CSV、Parquet 等；核心关键点数组可理解为“帧 × 关键点 × XYZ”，具体名称和布局依版本及追踪器而异。
- **检查结果**：含二维关键点的标注视频、用于理解关键点布局的追踪器信息、对应标定信息。
- **动画工作流**：依据版本与配置导出 Blender 场景，继续进行角色适配与动画加工。
- **衍生分析**：可以在位置数据上开发角度、速度、节奏或对称性指标；动作评分与建议还需要领域定义及验证。

## 如何驱动 3D 人物

推荐把它视为角色动画的一种动作来源：

**三维关键点 → 骨架拟合/IK 求姿态 → 动作重定向 → 动画烘焙与修正 → 播放器驱动角色。**

目标角色需要具备网格、骨骼和蒙皮。适配过程需要处理骨骼对应、参考姿态、坐标轴、单位、身材比例、根位移和脚底接触。位置点通常不能唯一确定所有骨骼的扭转，需要使用骨架约束或其他假设；不能把三维点文件直接视为完整通用旋转动画。

Three.js、Unity、Unreal 是可选择的下游播放环境，并非这里已完成的 FreeMoCap 即插即用集成。应针对选定角色导出兼容动画，再实现循环、混合、过渡、优先级和打断。表情、口型、视线和行为决策也需要单独安排。

## 使用场景

| 场景 | 使用价值 | 仍需补齐 |
| --- | --- | --- |
| 动画与游戏 | 把真人表演转换成动作素材 | 角色适配、脚滑与穿插清理 |
| 运动教学 | 回放、比较关节轨迹与节奏 | 指标定义、领域解释 |
| 科研实验 | 获取结构化三维运动序列 | 精度验证、实验设计 |
| 互动装置 | 根据身体运动触发内容 | 动作识别、反馈设计、延迟优化 |
| 动作数据集 | 积累真人动作样本 | 标注、质量检查、骨架统一 |

## 对你的价值

在桌面女友“小云”项目中，FreeMoCap 可以提供专属真人表演，例如具有个人节奏的挥手、伸懒腰或问候动作。处理并适配到小云的骨架后，可以加入统一动作库，由现有对话和事件系统决定何时播放。

Kimodo 与 FreeMoCap 可以作为并列动作来源：前者根据描述生成动作，后者从真人表演还原动作。两个来源进入同一个角色动作库前，都需要统一骨架、坐标和质量标准。人物资产决定外观，动作资产提供运动，角色系统决定何时做什么。

## 工程组成与扩展

v2 使用 React/Electron 界面，通过 REST/WebSocket 与 Python/FastAPI 后端协作。相关组件包括 SkellyCam、SkellySync、SkellyTracker，以及标定、几何重建、后处理和导出模块。v2 有实时与离线流程；不能用旧版 FAQ 的实时能力描述替代对 v2 的判断。

可以扩展的方向包括更换姿态模型、增加数据质量评估、批量处理、固定角色重定向、统一动作库、增加动作识别及业务指标。运行速度需要根据具体硬件、模型、分辨率和相机数量实测。

## 能力边界与实施顺序

- 精度受时间同步、标定、遮挡、光照与关键点识别影响，平滑结果不自动意味着准确。
- 手部、面部、多人及导出兼容性应按具体版本验证。
- 关键点不直接等于力、力矩或机器人可执行控制命令。
- v2.0.0-alpha.25 的发布说明列出约 10% 的尺度偏差问题，这是一项版本已知问题，不是通用精度指标。
- 上游代码采用 AGPL-3.0；集成与分发应考虑其许可证要求。
- 建议实施顺序：**样例录像跑通 → 验证真实采集 → 适配一个角色 → 扩充动作与产品功能**。

当前本地实验网页使用合成教学数据；本项目尚未实测真实摄像头采集、上游推理性能或测量精度。全景图中的人物、骨架、曲线与射线为说明原理的示意图。
