01

AI 找出“这是手腕”

YOLOX 定位人体，RTMPose 或 MediaPipe 预测二维关键点。输出的是每台摄像头里的像素坐标。

02

标定建立空间关系

已知尺寸的 ChArUco 板帮助估计镜头参数与机位关系。一个像素点因而对应一条空间射线。

03

几何求解三维位置

FreeMoCap 使用 DLT 建立多视角约束，再用 SVD 求解。此实验采用平行双目的解析公式。

04

检查并整理骨架

把三维点投回画面检查误差，再做平滑、短暂丢点补偿和骨长约束。平滑不等于测量准确。

展开数学原理与代码对应

s [u, v, 1]ᵀ = K [R | t] [X, Y, Z, 1]ᵀ

K 表示内参，R、t 表示世界坐标到摄像头坐标的变换。每台摄像头提供两条线性约束，组合为 A·X = 0；SVD 求得齐次坐标，再除以最后一个分量得到 XYZ。

本页的双目公式假设两台相机平行、焦距一致且已去畸变。实际 FreeMoCap 支持更一般的多机位情况，并处理异常观测。

01
INPUT & SETUP

一定要连接多个摄像头，才能运行吗？

多视角三维重建需要至少两个有效视角；处理已有录像时，不必连接摄像头。真正需要的是多个视角的数据，以及与这些画面对应的标定信息。

A / 现场采集

摄像头接入电脑

两台或更多摄像头从不同角度，同时拍摄同一个人的动作。先标定，再采集与处理。

输入：实时画面 + 相机标定
B / 已有录像

导入后离线处理

使用提前拍摄、时间对齐的多角度录像，以及对应标定数据。计算阶段可以断开摄像头。

输入：同步视频 + 标定信息
两种方式都要满足同一次动作同一时刻对齐共同看见目标点相机移动后重新标定
只有一个摄像头，或者暂时没有摄像头呢？

单摄像头可用于采集或二维识别，但不能完成多视角三角测量。单目 AI 可以根据学到的人体规律推断深度，那是另一种估计方式。

没有摄像头也能先用已有的合格样例录像研究流程，或在本实验室观察合成骨架与几何关系。不同时间分别拍的正面、侧面视频，不能直接当作同步多视角录像。

02
HOW IT WORKS

“多角度拍摄，再算法合成”具体是什么？

更准确的名字是多视角三维重建。AI 找出画面里的身体部位，几何算法计算空间位置，再把每一帧的位置连成动作。

  1. 01

    同步画面

    确保不同摄像头看到的是同一时刻的动作。

  2. 02

    标定相机

    用已知尺寸的 ChArUco 板，求镜头参数、畸变、机位关系与尺度。

  3. 03

    AI 找关键点

    RTMPose / MediaPipe 等识别各画面里的肩、肘、手腕、髋、膝。

  4. 04

    几何求三维

    去畸变，组合多视角约束，用 DLT + SVD 求每个点的 XYZ。

  5. 05

    整理动作序列

    检查重投影误差，处理异常、抖动与缺失，按流程施加骨架约束。

以抬起右手为例

两个视角，共同定位同一只手腕。

A 画面给出一条从相机出发的空间射线，B 画面提供另一条。理想情况下射线相交；真实观测有误差，需要求符合多个视角约束的位置。

处理的是坐标与时间序列。相机不同步、关键点被遮挡或标定不准，都会影响重建；平滑并不等于准确。

深度 = 焦距 × 机位间距 ÷ 视差

04
FROM DATA TO A MOVING CHARACTER

都是动作文件，就能让 3D 人物动起来吗？

最终可以，但要把动作适配到人物骨架。FreeMoCap 的核心数据是关节点位置；驱动角色还要得到目标骨骼所需的姿态与旋转，处理参考姿态、坐标轴、单位和身材比例。

人物资产她长什么样

网格 + 骨骼 + 蒙皮

动作资产她怎么动

随时间变化的位置与姿态

角色系统她何时做什么

选择、播放、混合与打断

  1. FreeMoCap

    三维关键点

    还原真人运动的坐标序列。

  2. 后续适配

    求骨架姿态

    骨架拟合 / IK，把点的位置转换成骨架姿态。

  3. 后续适配

    动作重定向

    对齐骨骼、参考姿态与身材比例。

  4. 动画制作

    烘焙与修正

    处理脚滑、穿插、根位移和动作衔接。

  5. 你的产品

    驱动人物

    通过 Three.js、Unity 或 Unreal 等播放器执行。

先有能被驱动的身体

只有漂亮外观的静态模型，需要先绑骨与蒙皮。动作数据通常不能唯一确定所有骨骼扭转，也不是任意人物都可直接播放的通用文件。

再补齐角色表现

面部表情、说话口型、视线与行为决策需要单独设计。FreeMoCap 提供动作来源，不自动完成整个桌面女友系统。

这里展示的是集成路线。本实验室尚未完成真实角色的重定向或播放引擎接入。

05
KIMODO × FREEMOCAP

和前面研究的 Kimodo，有什么本质差异？

Kimodo 根据描述生成动作，FreeMoCap 从真人表演中还原动作。它们可以成为同一个角色的两种动作来源。

比较维度KimodoFreeMoCap
输入文字、关键姿态、运动路径等约束多视角同步画面 + 对应标定数据
底层方法动作扩散模型，根据条件逐步生成动作序列AI 二维识别 + 多视角几何重建 + 时序处理
输出重点关节位置、旋转与身体移动等生成数据关节点随时间变化的三维位置数据
同样是挥手输入“开心地挥手”，生成一种表演拍下你的挥手，还原你的动作与节奏
核心价值创作新动作、产生多个版本采集真实表演、保留动作特征
共同的下一步适配目标角色骨架，检查修正后，交给动画播放器使用。

工程组成与可以扩展的方向

v2 的 React / Electron 界面通过 REST / WebSocket 与 Python / FastAPI 后端协作。相关组件包括 SkellyCam、SkellySync、SkellyTracker，以及标定、三角测量、后处理和导出模块。

可以扩展：替换姿态模型、增加质量评估、批量处理录像、统一动作库、开发固定角色重定向，以及面向具体场景的动作指标。

它把常见设备、预训练模型与几何计算组织成完整流程，降低了获取动作数据的门槛；实际搭建、性能和质量仍需要验证。
