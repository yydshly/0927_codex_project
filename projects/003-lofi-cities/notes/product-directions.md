# 产品价值与扩展方向

以下是产品假设，不是原站已有功能或 SDK 文档。

## 四层价值

| 层次 | 已观察基础 | 可积累价值 |
| --- | --- | --- |
| 场景 | 城市辨识度、像素夜景与动画 | 审美与内容识别 |
| 声音 | 实时音乐说明、能量/乐器/声源控制 | 可调节且适合长期使用的氛围 |
| 工作流 | 候播、计时、游城 | 减少选择、形成使用节奏 |
| 输出 | PNG、全屏、悬浮、OBS 入口/说明 | 进入工作与创作场景 |

值得积累的是场景内容和声音调校。增加城市属于内容扩充；把环境与任务绑定，更值得用于验证回访。

## 扩展方向

| 方向 | 最小新增能力 | 首先验证 | 主要约束 |
| --- | --- | --- | --- |
| 个人专注空间 | 整套预设、保存恢复、任务入口 | 是否反复启动同一环境 | 避免过早扩成任务管理系统 |
| 可嵌入组件 | 生命周期、配置协议、事件 | 两个宿主是否能复用同一接口 | 授权、性能、音频策略和兼容性 |
| 创作者背景 | 直播状态预设、干净输出 | 是否用于下一次真实直播 | OBS、音频路由、稳定性、授权 |
| 共同专注房间 | 房间、共享计时、个人音量 | 固定搭档是否复用 | 实时服务、权限、状态一致性 |
| 场景编辑器 | 场景包规范、编辑预览 | 外部创作者能否产出可用内容 | 编辑器、资源约束、审核和版权 |

## 第一阶段

把城市、能量、乐器、声音配比和周期保存成预设，再围绕写作或阅读恢复。观察复用与重复会话，不先假定商业转化和留存收益。

本地 web/preset.js 提供最小配置和三种样例。这是独立演示，没有调用原站 API；接入真实引擎仍需生命周期、版本迁移、声源映射与能力兼容处理。

## 新增理解与当前进展

上述早期假设中的组合、保存恢复与专注能力已在栖间成品中落地。最新定位、现有能力边界及后续路线见 [个人氛围空间理解](product-understanding.md)，对应 [网页栏目](http://127.0.0.1:4313/#understanding)。当前优先考虑视听品质和物件交互，再扩展规则联动、编辑分享及桌面创作工具。
