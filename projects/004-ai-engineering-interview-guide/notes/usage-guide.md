# 使用场景与学习指南

[返回概览](../README.md) · [能力地图](capability-map.md) · [公司索引](company-index.md)

本页为本项目的使用建议。路线、时间安排和评价方法不是上游自带功能，也不是公司的官方面试标准。

## 按目标选择路线

| 目标 | 优先阅读 | 建议产出 |
| --- | --- | --- |
| AI 应用工程 | RAG、Agent、评估、系统设计与目标公司 | 说明数据、权限、质量和成本的项目复盘 |
| 推理与平台工程 | 原理、推理性能、编程与可观测性 | 有指标和对照结果的性能实验 |
| 研究工程与后训练 | 原理、微调对齐、机器学习基础与评估 | 可复现的小实验及假设、结果、局限 |
| 客户交付与解决方案 | 系统设计、客户场景、安全与项目表达 | 一页需求澄清和试点验收方案 |
| 补齐已有项目能力 | 从最难解释的设计或故障切入 | 待验证假设与改进清单 |

岗位要求以实际招聘说明为准，路线只帮助选择起点。

## 学习循环

1. 选一个主题，挑 5—8 条题；有求职目标时再补公司专项题。
2. 先不查资料，给每题写短答案，标记不确定之处。
3. 查答案链接，必要时补论文和官方文档，记录证据与反例。
4. 对可实现的题做最小验证；对设计题说明约束、数据流和评估方案。
5. 用几分钟讲清问题、方案、取舍和边界。
6. 回访薄弱题，记录变化，不只标记“已读”。

## 个人复习模板

这是可复制的手工记录表，本子项目没有自动评分或进度同步功能。

| 字段 | 填写内容 |
| --- | --- |
| 主题 / 公司 | 主题及目标公司，公司可留空 |
| 原题链接 | 对应版本或章节 |
| 初始答案 | 不查资料时能说清什么 |
| 未理解之处 | 明确到公式、假设、机制或边界 |
| 补充材料 | 文章、论文、官方文档与阅读日期 |
| 验证结果 | 实现、测试、计算或设计推演 |
| 技术取舍 | 一个替代方案及取舍理由 |
| 掌握状态 | 待学习 / 能解释 / 能验证 / 能分析取舍 |
| 下次复习 | 要继续验证的问题和日期 |

## 约 60 分钟的模拟面试

| 时长 | 内容 | 观察重点 |
| --- | --- | --- |
| 10 分钟 | 概念解释与追问 | 假设清楚，机制准确 |
| 20 分钟 | 编程或故障分析 | 澄清需求，处理边界 |
| 20 分钟 | 系统设计与取舍 | 数据、评估、权限、成本和失败处理 |
| 10 分钟 | 项目复盘与反馈 | 区分事实、个人贡献和推测 |

按“概念准确、推导清楚、验证充分、取舍合理”记反馈。表现不能直接换算成某家公司的通过概率。

## 转成练手项目

以下方案需要另行实现：

| 方向 | 最小范围 | 验证重点 |
| --- | --- | --- |
| 文档问答 | 小型文档集、检索、回答和引用 | 检索命中、答案依据、失败案例 |
| 工具型 Agent | 少量工具、状态、错误处理与终止 | 工具失败、重复调用、预算耗尽 |
| 推理性能观察 | 固定模型和请求集，只改变一个配置 | 延迟、吞吐、资源占用和输出质量 |
| 提示或模型评估 | 固定测试集，对比两个版本 | 平均表现、退化案例与上线判断 |

基础较弱时先补编程、概率统计、线性代数和机器学习；缺少项目经验时增加实现与排障；用于团队招聘时需要另行制定与实际工作一致、可复核的评价标准。
