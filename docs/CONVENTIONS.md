# 新增项目与维护约定

## 1. 创建项目

在仓库根目录运行，将以下示例值替换成实际项目：

```sh
python scripts/projects.py new example-project --name "项目名称" --source "https://github.com/owner/repo" --summary "一句话说明研究价值"
```

脚本分配当前最大编号的下一个编号，复制模板并更新首页。短名称使用小写英文字母、数字和单个连字符，例如 `browser-use`。还没有真实研究对象时保持索引为空。

生成的目录：

```text
projects/001-example-project/
├── project.json       # 名称、摘要、顺序、状态、演示与图片信息
├── README.md          # 研究概览、运行方法、效果图与结论
├── notes/research.md  # 版本信息、阅读记录、实验结果与后续问题
├── assets/            # 项目截图、流程图和图片来源说明
└── web/               # 可选的 Web 演示及运行、构建说明
```

需要保留额外实验代码时，在该项目下创建 `experiments/`。上游源码可按需克隆到该项目的 `upstream/`，该目录默认不提交；在笔记中记录准确的上游提交。

## 2. 更新索引信息

编辑各子项目的 `project.json`。字段示例如下（仅说明格式，不代表已收录）：

```json
{
  "id": 1,
  "order": 1,
  "slug": "example-project",
  "name": "项目名称",
  "summary": "一句话说明研究价值",
  "source": "https://github.com/owner/repo",
  "status": "待研究",
  "demo": "",
  "cover": "",
  "cover_alt": ""
}
```

| 字段 | 维护方式 |
| --- | --- |
| `id` | 固定身份编号，显示时至少补齐三位；不修改、不复用 |
| `order` | 首页展示顺序，按数字升序；相同时按 `id` 升序 |
| `slug` | 与目录名对应，创建后保持稳定 |
| `name` / `summary` | 对外名称和一句话研究摘要 |
| `source` | 上游 GitHub 仓库链接 |
| `status` | `待研究`、`研究中`、`已完成` 或 `已归档` |
| `demo` | 验证可访问后填写的完整 HTTPS 演示链接；未部署留空 |
| `cover` | 相对子项目目录的真实图片路径，例如 `assets/cover.webp` |
| `cover_alt` | 图片所展示内容的文字说明；有封面时必须填写 |

运行以下命令更新并检查首页；自动生成区域以外的首页介绍会保留：

```sh
python scripts/projects.py sync
python scripts/projects.py check
```

首页索引表和图片展示使用相同的排序规则。未提供图片或演示的项目不会生成失效占位链接。`check` 会检查编号、目录名、必填字段、链接格式、图片存在性及首页是否同步，不检查外部网站的在线状态。

## 3. 补充图片和研究记录

1. 将截图放入项目的 `assets/`，文件名使用英文、数字、连字符或下划线。
2. 选一张适合首页的图片，在 `project.json` 中填写 `cover` 和 `cover_alt`。
3. 更多截图放在子项目 README，用相对路径引用，例如 `![主界面与任务列表](assets/overview.webp)`，并紧接着说明图片展示的功能或现象。
4. 更新 `notes/research.md`，记录实际运行环境、上游提交、操作步骤和观察结果。
5. 更新研究状态，重新生成索引并提交相关文件。

只有添加真实文件后才插入图片引用。区分自己的实测结论与上游说明，未验证内容明确标注“待验证”。

## 4. 归档与排序

归档时把 `status` 改为 `已归档`，保留目录、元数据和编号。需要优先展示某个项目时仅修改 `order`，不重新编号或重命名旧目录。多个分支同时创建项目时，合并前检查编号冲突并为尚未发布的新增项目分配空闲编号。

## 5. 提交前检查

运行 `python scripts/projects.py check`，并检查本次研究项目自身的运行和构建结果。仓库的自动检查负责索引与元数据；子项目引入实际代码后再增加对应的测试或构建检查。
